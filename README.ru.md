# README.ru.md

# adguard-stealth-dns

Однокомандный развёртыватель, превращающий свежий VPS под Debian/Ubuntu в публичный
**резолвер только DNS-over-HTTPS (DoH) + DNS-over-TLS (DoT)** на базе AdGuard Home,
где корень домена отдаёт правдоподобный сайт-приманку, а админ-панель AdGuard
живёт за длинным секретным путём (без HTTP Basic Auth).

## Что получается

- Публичные резолверы по адресу `https://<domain>/dns-query` и `tls://<domain>:853`. Без обычного DNS.
- Сайт-приманка «корпоративный файловый менеджер» на `/` (и на любом другом пути), чтобы сканеры видели безобидную страницу.
- Админ-панель AdGuard — только по адресу `https://<domain>/<secret>/`, перенаправляя на собственную страницу входа AdGuard; сам секретный путь и есть слой обскурации.
- Один сертификат Let's Encrypt, общий для Caddy (на `:443`) и AdGuard (на `:853`).
- Идемпотентно, продолжаемо возобновлять, логи в `/var/log/adguard-deploy.log`.

## Быстрый старт

```bash
git clone <этот-репозиторий>
cd adguard-stealth-dns
sudo ./install.sh
```

Установщик задаст несколько вопросов, сохранит ответы в `deploy.env` (mode `0600`)
и выполнит 8 шагов:

| Шаг | Что делает |
|---|---|
| 00-preflight | ОС, интернет, DNS указывает на этот сервер, нужные порты свободны |
| 10-base | пакеты apt, часовой пояс |
| 20-firewall | жёсткий UFW (SSH + 80 + 443 + 853) |
| 30-caddy | установка Caddy, остановка для проверки на порту 80 |
| 40-cert | certbot (standalone) + общий сертификат + deploy-хук |
| 50-adguard | AdGuard Home из официального установщика + патчинг конфига |
| 60-decoy | загрузка HTML приманки (в папке проекта есть встроенная копия) |
| 70-caddyfile | генерация + проверка + запуск виртхоста Caddy |
| 80-verify | smoke-тесты (DoH, приманка, редирект секретного пути, сертификат DoT, слушатели) |

Каждый шаг можно возобновить: уже выполненные пропускаются. `--force` — повторить все шаги.

## Предварительные требования (до запуска)

- VPS под **Debian 12/13** или **Ubuntu 22.04/24.04** с публичным IPv4.
- Доступ root.
- Запуск от root (или через `sudo -i`).
- **Имя хоста, чья A/AAAA-запись уже указывает на IP VPS** — скрипт откажется продолжать, если DNS не разрешается на этот сервер (можно обойти через `--yes`).
- Входящие порты **80, 443, 853** доступны из интернета (проверьте файрвол провайдера **и** UFW).
- Никто не должен уже слушать на **80, 443, 853** (скрипт предупредит, но не остановит чужие сервисы).
- Знайте свои остальные порты: скрипт спросит перед включением файрвола, и по умолчанию **запретит входящий трафик** на всё, кроме SSH + 80/443/853.

## Использование

```bash
sudo ./install.sh                      # интерактивно
sudo ./install.sh -y                   # принять предложенные значения (только после deploy.env)
sudo ./install.sh --yes                # то же
sudo ./install.sh --config ./prod.env  # конкретный файл конфигурации
sudo ./install.sh --force              # повторить все шаги
sudo ./install.sh --only 50-adguard    # выполнить один шаг
sudo ./install.sh --uninstall          # снести всё
```

Конфигурация может задаваться и через переменные окружения (наивысший приоритет):
`DOMAIN`, `EMAIL`, `SECRET_PATH`, `ADMIN_USER`, `ADMIN_PASS`, `TIMEZONE`,
`SSH_PORT`, `EXTRA_ALLOW`, `SKIP_FIREWALL`, `DO_UPGRADE`,
`ENABLE_DEFAULT_FILTERS`, `DECOY_URL`, `ADGUARD_UPSTREAMS`,
`ADGUARD_BOOTSTRAP`, `ADGUARD_FALLBACK`.

После первого интерактивного запуска они сохраняются в `deploy.env` (mode `0600`). **Храните файл приватно.**

## Примечания по безопасности

- AdGuard привязывает админку/DoH **только** к `127.0.0.1:3000`; DoT открыт на `:853`; обычный DNS и DoQ отключены.
- AdGuard работает от root (чтобы занять `:853`). Меняйте, если понимаете последствия.
- Секретный путь — это и есть весь слой обскурации: выбирайте длинное и непредсказуемое значение (установщик генерирует его по умолчанию) и никогда не публикуйте.
- **Не запускайте** `certbot renew --dry-run` бездумно: deploy-хук скопирует staging-сертификат на место боевого.
- В этой версии (0.107.x) `AdGuardHome --check-config` может зависнуть и захватить `:3000`. Шаг `50-adguard` его намеренно не использует. Проверяйте конфиги структурно.
- Форма приманки работает только на стороне клиента — нигде не отправляет учётные данные.

## Откат

Резервные копии, созданные при установке, остаются на сервере:
`/root/AdGuardHome.yaml.bak.<timestamp>`. Примените нужную вручную или выполните `./install.sh --uninstall`.
